# ADR-018: candidate-bound engineering child collection

Status: accepted for the execution pilot; credentialed acceptance pending. Date: 2026-11-14.

Decision: enable telemetry only through a private operator configuration bound into the immutable engineering manifest. After four successful engineering stages, freeze a source-candidate recipe digest, manifest plan digest, policy fingerprint and observation window. Optionally publish the already-reviewed draft before the wait so independently authorized preview tooling can obtain it. Start one finite telemetry child workflow per configured backend on a dedicated queue. The parent awaits all outcomes and verifies actual authenticated evidence before review readiness and around publication side effects.

The candidate recipe binds repository, immutable base Git commit and sorted complete replacement edits. It is explicitly a source artifact, not an OCI image digest or deployment attestation. Map both digests into source labels/resource attributes and validate returned values; attaching a binding only to an upload envelope would allow unrelated measurements to appear attributable. Require the configured evidence producer, content hash, exact source profile, context, preview generation, fixed window and unexpired timestamps. Partial/empty/search-only telemetry cannot satisfy the readiness requirement. No query observation becomes a 120-check certification verdict.

Alternatives: collecting on a free-running timer before the candidate exists cannot reliably identify the candidate; invoking network clients directly from the workflow breaks deterministic replay and source credential isolation; collecting before draft publication prevents an independently authorized preview builder from obtaining the candidate. A perpetual parent collection loop expands authority and history without a bounded review outcome.

Consequences: operators provide private source mappings, a telemetry worker, bounded preview preparation delay and a prearranged full trace ID where Tempo is required. Candidate export is read-only and starts no workflow. Prepared windows survive retries; missed windows require a newly reviewed execution. Cancel/parent-close requests cancel children, subject to worker availability and hard timeouts. Existing histories follow their recorded prepare result and keep their original path. Enabling policy changes mid-run fails manifest validation. Drafts/evidence already committed are retained after failures. Live schema/tenant acceptance, build provenance, cross-host recovery and deterministic certification remain separate work.
